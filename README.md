# PADALI — сайт группы

Одностраничный сайт на двух языках (EN/SR) с блочной админкой.
Текстовый контент — в PostgreSQL, изображения — на диске, разделы страницы
собираются из блоков и переставляются мышью.

- **Стек**: Node.js 22, Fastify, PostgreSQL 16, шаблоны Eta (рендеринг на сервере)
- **Админка**: на языках сайта (EN/SR), блоки, медиатека, альбомы, администраторы, статистика
- **Деплой**: Docker, Coolify
- **Спецификация**: [docs/superpowers/specs/2026-10-03-padali-cms-design.md](docs/superpowers/specs/2026-10-03-padali-cms-design.md)

---

## Запуск локально

```bash
npm install
npm run db:up        # PostgreSQL 16 в контейнере на порту 54321
npm run seed         # миграции + перенос исходного контента + создание админа
npm run dev          # http://localhost:3031
```

Админка: `http://localhost:3031/admin`, вход из `.env.development`.

Остановить базу: `npm run db:down`.

### Тесты

```bash
docker exec padali-pg-dev psql -U padali -d padali -c "CREATE DATABASE padali_test;"
npm test
```

## Деплой в Coolify

1. Подключить репозиторий, тип приложения — **Docker Compose**.
2. Задать переменные окружения (см. `.env.example`). Обязательны:
   `DB_HOST`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `SESSION_SECRET`,
   `PUBLIC_URL`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`.
   Секрет сессий: `openssl rand -hex 32`.

   База — внешний PostgreSQL, заведённый в Coolify. `DB_HOST` — его
   внутреннее имя сервиса. Приложение живёт в отдельной схеме
   (`DB_SCHEMA`, по умолчанию `padali`), поэтому базу можно делить
   с другим проектом, не смешивая таблицы.
3. Добавить **persistent storage** на `/app/data/uploads` — там лежат
   загруженные изображения. Без тома они пропадут при следующем деплое.
4. Развернуть. При первом старте приложение само применит миграции,
   перенесёт контент исходного лендинга и создаст администратора.
5. Войти в `/admin`, сменить пароль не нужно — он задан переменными;
   после первого входа `ADMIN_EMAIL` и `ADMIN_PASSWORD` можно удалить.

Файл `.env` в репозиторий не попадает: переменные задаются в интерфейсе Coolify.

## Из чего состоит

```
src/
├─ blocks/         дескрипторы типов блоков — реестр расширяемости
├─ db/             пул соединений и миграции
├─ repositories/   единственное место, где есть SQL
├─ services/       сборка страницы, обработка картинок, рендеринг, авторизация
├─ routes/         HTTP: публичная часть и админка
└─ views/          шаблоны Eta: раскладка, блоки, админка
public/            css, js, брендовые ассеты
seed-assets/       картинки, которыми управляет репозиторий
data/uploads/      загруженные изображения (том, в git не попадает)
```

### Как устроен контент

| Таблица | Что хранит |
|---|---|
| `blocks` | блок на странице: тип, позиция, видимость, якорь, непереводимые настройки |
| `block_texts` | весь переводимый текст блока, строками `(язык, поле, значение)` |
| `block_media` | связи блока с изображениями |
| `galleries` + `gallery_items` | альбомы и их состав |
| `media` + `media_texts` | файлы, их размеры и описания |
| `pages` / `page_texts` | страница и её мета-теги |

Все таблицы лежат в схеме `padali` — отдельно от таблиц соседних
проектов в той же базе.

Добавление языка — вставка строки в `locales`, а не изменение схемы.
Если перевода поля нет, показывается значение языка по умолчанию.

## Как добавить новый тип раздела

Два файла, без миграций:

**1. Дескриптор** `src/blocks/<тип>.js` — админка построит форму по нему:

```js
export default {
  type: 'video',
  title: 'Видео',
  description: 'Встроенный ролик с подписью.',
  texts:    [{ key: 'heading', label: 'Заголовок', input: 'text' }],
  media:    [{ key: 'poster',  label: 'Превью' }],
  settings: [{ key: 'url', label: 'Ссылка на ролик', input: 'url', required: true }],
  template: 'blocks/video'
}
```

**2. Шаблон** `src/views/blocks/video.eta`:

```eta
<section class="section wrap"<% if (it.block.anchor) { %> id="<%= it.block.anchor %>"<% } %>>
  <% if (it.block.text.heading) { %><h2><%= it.block.text.heading %></h2><% } %>
  <!-- it.block.settings.url, it.block.first('poster') -->
</section>
```

**3.** Подключить дескриптор в `src/blocks/index.js`.

Доступные типы полей: `text`, `textarea`, `richtext`, `number`, `checkbox`,
`select`, `date`, `url`, `repeater`, `image-picker`, `gallery-picker`.
Поля из `texts` автоматически получают по инпуту на каждый язык.

## Фотогалерея

Альбом и место показа разделены: фотографии лежат в альбоме (`/admin/galleries`),
а блок «Фотогалерея» только ссылается на альбом и задаёт вид.

Поэтому можно:

- поставить на страницу **несколько галерей с разными альбомами**;
- вставить **один альбом в нескольких местах** с разной раскладкой — например,
  лентой из четырёх кадров вверху (`Показать первые N` = 4) и полной сеткой ниже;
- править порядок и подписи **один раз в альбоме** — обновятся все вставки.

Раскладки: сетка, горизонтальная лента, кладка. Число колонок, лайтбокс и
подписи настраиваются в блоке.

## Изображения

При загрузке `sharp` делает webp-версии шириной 320/640/1280/1920/2560 и
**всегда добавляет полную ширину оригинала**. Последнее важно: без него
`srcset` обрывался бы на предыдущей ступени — у снимка 1100 px лучшим
кандидатом оказывался бы 640 px, и браузер растягивал бы его на всю шапку.

Файлы кладутся в `data/uploads/ГГГГ/ММ/`, имя — SHA-256 содержимого:
повторная загрузка того же файла не создаёт дубль, отдача идёт с
`Cache-Control: immutable`. Мелкие версии сжимаются сильнее (q82),
крупные — мягче (q88), потому что идут на весь экран.

Файл нельзя удалить, пока он используется хотя бы в одном блоке или альбоме.

Если лестница ширин менялась, уже загруженные пользователем картинки
пересобираются командой `npm run rebuild-derivatives`. Файлы репозитория
(см. ниже) чинятся сами при следующем запуске.

## Статистика посещений

Страница `/admin/analytics`: просмотры и посетители за период, столбики
по дням, сетка «день недели × час» и карта кликов поверх живой страницы.

Считается своим кодом, без кук и без внешних сервисов. Посетитель
опознаётся хешем от адреса и браузера с солью, в которую входит дата:
за сутки видно уникальных, между сутками связать визиты невозможно.
IP-адрес не сохраняется. Боты, админка и запросы с `DNT: 1` не считаются.

Сырые события живут `ANALYTICS_RETENTION_DAYS` дней (по умолчанию 180)
и чистятся при старте и раз в сутки.

Карта кликов показывает страницу во фрейме размером с настоящий экран
и рисует пятна поверх.

Клик хранится **относительно блока**, в котором случился: пиксели от
центра блока по горизонтали и от его верха по вертикали. От окна
браузера координаты считать нельзя — высота шапки задана в единицах
экрана, а колонка содержимого центрирована, поэтому у посетителя с
другим окном та же кнопка оказывалась бы в другом месте.

Карта верна, пока вёрстка блока не менялась: если переставить
элементы внутри него, старые клики окажутся не на своих местах.

## Логотип

Логотип сайта выбирается в настройках из медиатеки и показывается в
шапке, а также в hero и подвале, когда там нет своего. Загружать нужно
**прозрачный** PNG или WebP со светлыми буквами — шапка тёмная.
Встроенный логотип нарисован чёрным и осветляется фильтром; к
загруженному фильтр не применяется, чтобы редактор видел ровно тот
файл, который выбрал.

## Два способа поменять картинку

**Через админку** — обычный путь для группы. Медиатека → загрузить →
в блоке выбрать новый файл. Репозиторий в это место больше не вмешивается.

**Заменой файла в репозитории** — путь для разработчика. Картинки из
`seed-assets/` помечены ключом (имя файла без расширения) и остаются
управляемыми: положите на место `seed-assets/band-photo.png` другой файл,
выкатите — при следующем запуске содержимое записи в медиатеке
заменится **на месте**. Идентификатор не меняется, поэтому все ссылки из
блоков и альбомов продолжают работать и показывают новое изображение;
прежние файлы удаляются с диска.

Правило старшинства: **человек главнее файла в git**. Если в админке для
блока выбрали другую фотографию, замена файла в репозитории её не
затронет — запись репозитория обновится, но блок на неё уже не смотрит.
В логе запуска это видно: `используется в блоках: 0`.

Добавление нового файла в `seed-assets/` кода не требует, но сам по себе
он на странице не появится — его нужно вставить в блок через админку.
